# L1.5 风险分级接线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 spec-runner 加 `risk` 子命令，汇总变更 input → opa 评估 `policy/risk.rego` → 输出 `{level, deny}`，并接到 CI 门禁（deny 阻断）。这是 L1.5 的入口能力。

**Architecture:** 复用已有的 `affected.collect_affected()`（changed_files/lines）拼 risk.rego 的 input，subprocess 调 `opa eval` 评估 rego，输出等级与 deny。opa 缺失明确报错（CI 用 setup-opa，本地 brew）。阶段 1 不动 branch protection，只做"评估 + deny gate"，R0 自动合并留阶段 2。

**Tech Stack:** Python 3.13（spec-runner 现状）· OPA（rego 评估）· GitHub Actions（CI gate）· pytest（TDD）

**阶段 1 边界（决策点 B）：** `dangling_selectors` 与 `boundary_violations` 在 `affected.py` 已占位为空/0，阶段 1 沿用——`risk.rego` 的 deny 规则因此阶段 1 不会触发，只输出 level。boundary 实填（扫所有 specs 的 allowed_changes 并集 vs changed）留阶段 2。这足以验证分级逻辑（R0-R3 的路径/行数规则）。

```python
def evaluate_risk(input_data: dict, policy: Path | None = None) -> dict:
    """opa 评估 risk.rego → {level, deny}。opa 缺失抛 FileNotFoundError。"""
    opa = shutil.which("opa")
    if opa is None:
        raise FileNotFoundError(
            "opa 未安装：brew install opa（CI 用 open-policy-agent/setup-opa action）")
    policy = policy or (POLICY_DIR / "risk.rego")
    import tempfile
    with tempfile.NamedTemporaryFile("w", suffix=".json", delete=False) as f:
        json.dump(input_data, f)
        input_file = f.name
    try:
        proc = subprocess.run(
            [opa, "eval", "--format=json", "--data", str(policy),
             "--input", input_file, "data.kite.risk"],
            capture_output=True, text=True)
    finally:
        Path(input_file).unlink(missing_ok=True)
    if proc.returncode != 0:
        raise RuntimeError(f"opa eval 失败（退出 {proc.returncode}）: {proc.stderr}")
    val = json.loads(proc.stdout)["result"][0]["expressions"][0]["value"]
    return {"level": val.get("level"), "deny": list(val.get("deny", []))}
```
